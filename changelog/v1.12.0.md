## [1.12.0] - 2026-11-26

Every tap shows it was heard: a button that sent a request carries a moving sheen until the answer arrives and won't send it twice. A camera scanner that opens one camera and closes it, loads its decoder once and says why it couldn't start. Borrow requests, recommendations and connections are declared as state machines. And Hono 4.13.16, with five security fixes.

### Changed

- **Every request shows it is on its way.** The button or form that sent it carries `aria-busy` with a moving
  sheen (a dotted ring with reduced motion) until the answer is in, so a tap on a slow connection no longer looks
  like nothing happened. A plain form (Save, Lend, Add) refuses a second submit while the first is out (ARCH.md
  §16 #105).
- **The status columns that move are declared as state machines** in `src/lib/lifecycles.ts`: borrow requests,
  recommendations and connections. Every statement takes its moves from there, and
  [docs/state-machines.md](../docs/state-machines.md) draws them, checked by a test. Nothing changes in what moves
  where.
- **On a touchscreen**, the Edit, Add a past read, Add a cover and History toggles are a finger's height. A read's
  Began and Ended fields say which is which.

### Fixed

- **The camera scanner** no longer opens a second camera on a double tap of Start. It no longer leaves the camera on
  when the camera answers after the 8-second timeout, or after Stop. On a slow connection it loads the barcode
  decoder once, not once per frame, and reads one frame at a time. Its message says why the camera didn't start:
  permission refused, timed out, or no HTTPS.
  A decoder download that fails no longer leaves the scanner dead for the page and still saying "Loading": it says
  it couldn't load and tries again. Focus on Start moves to Stop when the camera goes live.
- **A double tap on the Add page's Look up or Search** no longer asks the providers twice (htmx queued the repeat
  and sent it after the first). A new search while one is out still goes.
- **The Add page's review list** no longer misses a barcode held while it was already reading the device's queue
  (scanning fast with Keep scanning on).

### Security

- **Hono 4.13.16**, the web framework every page runs on, with five advisories fixed. The one that touches
  Nalanda is GHSA-h7mg-cq63-vhpq: the default router could skip a middleware added without a path for some
  addresses, such as one with an encoded line break, and the sign-in check is one. Probing 4.13.14 found no address
  that reached a signed-in page without a session, since every address that skipped the check also matched no route,
  but the fix belongs in production rather than relying on that. The other four (`mount()`, `validator('form')`,
  the `css` helper, `csrf()`) are in parts Nalanda doesn't use.
- **fast-xml-parser 5.12.0**, the BoardGameGeek XML parser: bug fixes, no advisory.
- **sharp 0.35.5** (GHSA-wq5f-xc86-pv6w, librsvg). A development dependency only: miniflare uses it to
  emulate the Images binding, which Nalanda doesn't use, so no deployed instance ever ran it on an image.
  The `overrides` pin in `package.json` moves from 0.35.4 to 0.35.5 (ARCH.md §16 #30).
- **Vitest 4.1.12** (two `@vitest/mocker` advisories, Dependabot). The test runner only: it never ships
  in the Worker, so nothing changes for a running instance.
- **undici 7.30.1** (five Dependabot advisories: TLS validation, renegotiation and WebSocket DoS,
  redirect cache poisoning, content-encoding DoS). It reaches the tree only through miniflare (local dev
  and tests), never the Worker bundle; the `overrides` pin in `package.json` moves from 7.29.1 to 7.30.1.

### Upgrading

- **No migrations, no new secrets, no manual steps: deploy as usual.** Nothing in the database changes, so no
  backup is needed beyond your usual.
- **Connections:** nothing here changes what households exchange. Connected households on older versions stay
  connected.
- **The service worker's version moves to 3**, so each device fetches the new scripts and stylesheet on its next
  visit. A tab left open since before the deploy keeps the old scripts until it is reloaded, which is harmless.
