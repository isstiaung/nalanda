### Fixed
- **The demo's share links, QR codes and feeds point at the demo.** The app writes a share's address in full, from the address a page was loaded at, so in the published demo they read `http://127.0.0.1:8818/…` — the scratch server the demo is built from — and the share pages themselves were never crawled. The build now takes the site's origin from Pages and points every such address at the demo's own copy, share pages and feeds included. [runbooks/demo.md](../runbooks/demo.md) also says how to let release tags publish it.

### Added
- **Members join with a link, not a password.** **Create account** under Members now shows a one-time invite link, with its QR code to scan from your screen. The new member opens it, chooses their own password and is signed in; you never see it. **Reset password** works the same way: the old password and every session end at once, and a reset link lets them choose another. A link works once, for seven days, and only its hash is kept; Members shows *Invited* or *Reset link out* until it's used ([runbooks/accounts-and-access.md](../runbooks/accounts-and-access.md), ARCH.md §16 #97).
- **Your devices, one by one.** Account → **Devices** lists every device signed in to your account (its browser and system, when it signed in, when it was last used), and **Sign out** ends any one of them. Log out now ends this device's session too, so a copy of its cookie signs nobody in. A session lasts 30 days from its last use rather than from sign-in, so a device you use keeps you signed in ([runbooks/accounts-and-access.md](../runbooks/accounts-and-access.md#sign-out-one-device), ARCH.md §16 #98).
- **Sign in a device from another one, either way round.** On a television or a borrowed laptop, skip the password: Account → **Devices** → **Sign in another device** shows a code to type there (or a QR to scan), good once for five minutes. Or tap **Sign in with your phone** on the log in page: scan the QR it shows with a phone that's signed in, type the number the new device shows, and it signs in ([runbooks/accounts-and-access.md](../runbooks/accounts-and-access.md#sign-in-a-device-without-its-password), ARCH.md §16 #99).
- **A way back in for an admin.** Setup now shows the first admin a **recovery code**, once. If you forget your password, **Forgot your password?** on the log in page takes your username, the code and a new password, and signs every other device out; you get a new code each time. Admins can make a new code under Account → **Recovery code** (it asks for your password). Failing that, whoever deploys the library can run `npm run reset-admin -- <username> --url=https://your.library` to make a one-time reset link ([runbooks/accounts-and-access.md](../runbooks/accounts-and-access.md#admin-lockout-you-forgot-the-admin-password), ARCH.md §16 #100).
- **Run your own from a fork, all in the browser.** Fork this repository, then in Cloudflare **Import a repository** and pick your fork: the first deploy creates the database and the cover bucket, migrates the database and deploys. Set `SESSION_SECRET`, open `/setup`, and you're running; each new release then arrives with GitHub's **Sync fork** button (backups, when a release asks for one, still need a terminal). Switch on R2 in your Cloudflare dashboard first: it's free, but Cloudflare asks for a card ([runbooks/deploy.md](../runbooks/deploy.md#run-your-own-from-a-fork), ARCH.md §16 #101).
- **`/setup` asks for the `SESSION_SECRET` first**, so only whoever deployed a new library makes its admin — a new library's address (`nalanda.<account>.workers.dev`) is easy to guess.

### Upgrading
- **One migration, 0059: a new `account_links` table, no data changed.** [Back up](../runbooks/backup-and-restore.md) first as before any migration, then deploy as usual. Backups carry the table after `users` (hashes only, as they carry API tokens), and the restore list in the backup runbook gains it. A member who still has a temporary password from before keeps it and changes it at first sign-in, as before.
- **One migration, 0060: a new `sessions` table, no data changed. Nobody is signed out:** a device already signed in stays signed in until its own 30 days are up, and appears under Devices once it signs in again. Backups leave the table out, so a restore signs out every device that signed in since this version. An account keeps at most 20 devices signed in; the least recently used signs out as a 21st signs in.
- **One migration, 0061: a new `device_pairings` table, no data changed.** It holds only requests open for five minutes; backups leave it out.
- **One migration, 0062: a new `recovery_codes` table, no data changed. Admins: make your recovery code.** An admin from before this version, or added under Members, has none: Account → **Recovery code** → **Make a recovery code**, and keep it somewhere apart from your devices. Changing your password, an admin's reset or a one-time link ends your code too: make a new one afterwards. Backups carry the table after `users` (hashes only), and the restore list in the backup runbook gains it.
- **Local development: set `SESSION_SECRET` in `.dev.vars`.** `.dev.vars.example` now leaves it empty, and the app refuses the sample value it used to carry, since anyone can read it: setup and login answer "Not ready yet" until a real one is set. If your `.dev.vars` still holds `change-me-to-anything-long-and-random`, replace it. `npm run seed:demo` reads it from there. A deployed instance with that sample as its secret would stop signing anyone in, too; set a new one (runbooks/troubleshooting.md).
