### Added
- **Two contributor guides.** [docs/adding-a-column.md](../docs/adding-a-column.md) and [docs/adding-a-provider.md](../docs/adding-a-provider.md) walk the two most common changes in order — the existing rules, sequenced — linked from CONTRIBUTING.md. Nothing in the app changes.
- **Borrowed from someone.** A book borrowed from a friend is in the catalog as Not owned, with a borrow record: on its page, under Circulation, **Borrowed from**, a contact, a due date and a note, and **Mark returned** when it goes back. A **Borrowed** pill shows beside Not owned on the item, on shelves and in search; the shelf's Holding filter gains **Borrowed from someone**. **Borrowed**, under Lending, is now for every household — what is borrowed from people, overdue flagged, and what was returned — with the connections sections following where connections are enabled. Private like loans: never on a share link, never to connections. Round-trips through the CSV as a `borrowed` cell, shaped like `loans`.
- **Author A–Z.** A shelf's sort gains the author's surname — the first creator's last name, or the name before the comma when a creator is written "Le Guin, Ursula K." — then their full name, then the title; items with nobody named come last. A share link can be published in that order too.
- **Import from StoryGraph and LibraryThing.** Both exports are recognised on the Import page and brought in as a Goodreads export is: a book already here (by ISBN, then title and author) gets your rating, review and reads merged onto it; the rest become Not owned reading-log entries — or owned copies where the file says so (StoryGraph's Owned?, LibraryThing's collections and Copies). StoryGraph's dated reads each become a read, its format the copy's form, its moods, pace and content warnings your private notes; LibraryThing's Date Read and Date Started, Media, Comment and Private Comment, Collections, Series and Volume, Languages all map. Two runbooks say how to export.
- **QR codes for share links.** Shared links shows a QR code beside each address — lampblack modules on palm-leaf, the Nalanda mark under its vermilion rule in the middle — with **Download PNG** for a card on the shelf or a note on the fridge. Drawn in your browser from the address already on the page; nothing new is published, and nothing is fetched from anywhere else.
- **Item history, for admins.** An item's page gains **History**: each change to one of its own fields — title, creators, shelf, holding, cover, notes, location, series, price, details — with who made it and when, from every path that changes an item (the form, the Holding toggle, bulk edit, a cover, a refresh from BGG or Discogs, an import), kept 90 days. Not reads, reviews or plays, which already say who. A removed member is "a former member". Members don't see it; nothing of it reaches share links or connections.
- **A read-only API, with tokens of your own.** **Account → API tokens** makes a token, shown once; with it a script or another app reads your library as JSON — `/api/v1/items` with a shelf's filters, 250 a page; an item with its reads, reviews and loans; search; loans; your want list and goal — and changes nothing. A token sees what you see and no more; it stops working when you sign out other devices or change your password, and you can revoke it any time. [runbooks/api.md](../runbooks/api.md).
- **Feeds for share links.** Every share link has an Atom and an RSS feed — `/share/<token>/feed.atom` and `.rss`, linked from the page's head so a reader finds them — of its twenty newest additions (a gift list's newest wants), each with the title, creators, cover, the household's rating and latest review, and a link to the item's share page. The same whitelist as the page; dated by when the item was added, never by anyone's reading. Cached with the page, gone with the token.
- **Date added, from the file.** A Goodreads, StoryGraph or LibraryThing import dates each new book by the file's Date Added or Entry Date (libib's `added` likewise) instead of the day of the import, so newest-first and "Unread for years" mean what they say. For the books already here, tick **Also set the date added of books already here from the file** on the Import page and re-import the same export: the preview says how many it would date, the summary how many it did. Off by default; nothing else about a book moves, and connections keep every reference they hold.

### Fixed
- **The login throttle now holds against guesses sent all at once, and counts per account as well as per address.** Ten wrong passwords in ten minutes from one address already locked it out, but a burst sent in parallel all reached the password check before any was counted; the attempt is now counted in the statement that checks the count, before the password is looked at, so a burst stops at ten too. The rule has changed in two ways: ten wrong guesses at one account, from however many addresses, lock that account out for ten minutes (the right password included — before, only the guessing address was slowed), and a household's shared address locks out only the accounts guessed at on it, not everyone behind it. The lockout page reads as it did and now answers HTTP 429, so a script can tell it from a wrong password. A login that succeeds counts towards nobody's ten.
- **Login no longer says, by how long it takes, which usernames exist.** A name nobody has was answered without checking a password, in a fraction of the time a wrong password took; it is now checked against a fixed stand-in hash, so both answers take the same work.
- **Guessing at your current password under Account is throttled like login.** Changing a password asks for the current one, and that check had no limit: whoever held a signed-in device could try passwords without end, and a right guess would have signed you out everywhere. Wrong answers there now count towards the same ten in ten minutes, by address and by account, and past it the page says "Too many attempts" (HTTP 429) — the account's login is locked out for those minutes too.
- **A temporary password reaches only the password change.** Signed in with a temporary password, a member could already open nothing but Account — but every action on that page still went through: a display name (which share pages show when names are on), **Sign out other devices**, revoking a token. Until their own password is set, those are sent back to the Account page, unchanged; logout works as before.
- **Members no longer offers "Reset password" on your own row.** A reset signs its account out everywhere — the device that clicked included — so an admin who reset themselves was signed out on their next click, with the temporary password shown once on a page about to go. Your own row now points at **Account**, where changing your password keeps this device signed in; a reset posted at your own account anyway is refused.
- **Signed-in pages are no longer kept by the browser.** On a shared phone, one person's logout followed by another's Back could show the first person's pages from the browser's own cache — notes, locations, who has what on loan, a temporary password just minted. Every signed-in page now tells the browser not to keep it (`Cache-Control: no-store`), and logging out clears the browser's cache of this site. Share links, covers and the login page are unchanged.
- **Static files carry the same protective headers as pages.** The offline page, scripts, stylesheet and icons are served by Cloudflare before Nalanda runs, so they went out without the headers every page has; a `_headers` file in `public/` now marks each one unframeable (`X-Frame-Options: SAMEORIGIN`) and `nosniff`. Nothing else about them changes: they still revalidate on every load.
- **A NUL byte in the search box answers a page, not "Something went wrong".** The full-text index read the byte as the end of its expression; it is now dropped, with the other control characters, and the words either side of it still search.
- **An operator beside a stray dash, ampersand or ellipsis lists what the operator lists.** `tag:fantasy &` and `status:unread -` found nothing where `tag:fantasy` and `status:unread` listed; a word with no letter or digit in it is now no word. `pratchett & gaiman` finds Good Omens as it did.
- **A saved view holds "Read by" as the menu writes it.** A view saved from a hand-typed `readBy=02` named member 2 and yet kept that filter when they were removed, so it would have listed whoever was given the id next under the old name. The id is stored without leading zeros, views saved before this are matched as numbers when a member goes, and the search box's menu shows such a value selected.
- **"On loan" and "Overdue" count every open loan.** The Overview and the Loans page counted a list that stops at the newest 200, so past that both numbers stuck at 200 and the oldest loans — the likeliest overdue — went uncounted. Both are now counted in the database; the Loans table still lists the newest 200 and says so when there are more.
- **New from your authors and a series' look-up read the shelves once.** The Discover page listed the shelves twice on every load, and a series' Open Library look-up read the series twice and the shelves twice; each now reads what it shows once, which leaves more of the day's database budget for everything else.
- **A Goodreads, StoryGraph, LibraryThing or Kindle import no longer merges one book onto another.** Matching by title and author reduced every title in Tamil, Cyrillic, Devanagari or CJK to nothing, so a second book by the same author merged its rating, review, notes and reads onto the first and was never added; and a title's subtitle was dropped before matching, so Brian Herbert's *Dune: House Atreides* merged onto Frank Herbert's *Dune*. Titles in every script now keep their words, a title with none left matches nothing, and a title-and-author match needs the whole first-author name to agree, initials aside — "Ursula Le Guin", "Ursula K. Le Guin" and "Le Guin, Ursula K." all still meet ([ARCH.md §16 #14](../docs/decisions/014-goodreads-csv-import-match-merge.md), amended).
- **Quotes keep their writer through a Nalanda re-import.** An admin importing a household's export got every quote as their own, a former member's included; a quote now stays with the member of that name, a former member's with nobody, as the reads and reviews beside it do.
- **A private column never lands in an item's details, whatever the file.** A `Location` or `Notes` column added to a Goodreads, StoryGraph or LibraryThing export before import, or the reading dates of a Nalanda export that lost a column in a spreadsheet and so was read as a libib file, were kept in the item's details — which share pages and connections show. One list of private columns now applies to every import: location and notes map onto their private fields in every format, and everything else private — reads and their dates, reviews, loans, plays, grades, prices, who added it — is dropped rather than kept. A Nalanda export read as libib also keeps its type, UPC and dates now, and the preview says when a file was read as libib.
- **The export never hands a spreadsheet a formula.** A cell beginning with `=`, `+`, `-`, `@`, a tab or a carriage return — a title a connected household recommended, say, that a member then wanted — opened in Excel, LibreOffice or Google Sheets as a live formula that could send the rest of the row elsewhere. Such a cell now leaves with a `'` in front, which spreadsheets read as "text" and don't show, and importing a Nalanda export strips exactly that one quote, so `=1+1` and `'quoted` come back as they went out ([ARCH.md §16 #91](../docs/decisions/091-csv-formula-guard.md)).
- **Who added an item survives an export and import.** The item page says who added each item, but the export never carried it, so a restored catalogue named the importer on everything. The export gains an `added_by` column — the username, empty for a member removed since — and an import gives the item back to the member of that name under the same rule as reads and reviews: in an admin's import, a name that is a member here keeps it; anything else, and any member's import, is the importer's.
- **A StoryGraph import keeps every dated read, first time and on a re-import alike.** A book the file added kept all its Dates Read ranges but ignored Read Count, so a re-import then added the undated reads the count asked for; a book already here kept only the last range and an undated stand-in for the rest. Now Read Count tops a new book's dated reads up with undated finishes, and a merge reconciles every range, so a second import adds nothing.
- **A libib group with a comma in it is several tags.** `sci-fi, classics` became one tag that the export wrote back as two; a group is now split on commas as the tags cell is.
- **An import takes only real dates.** A Goodreads, StoryGraph or LibraryThing date added or date read, or a Nalanda export's `added_at` edited by hand, was accepted on its shape alone, so `2024/13/45` could become an item's date added; a date is now a calendar date (and a time of day) or nothing, as every read's date already was.
- **A Goodreads ISBN cell that isn't an ISBN is no longer matched on.** `n/a 1` and `see note 1` were both reduced to the digit `1` and so matched each other, merging unrelated books on a later batch or re-import; an ISBN column now yields an ISBN (13 digits, or nine and a check digit, hyphens aside) or nothing, with the text kept in the item's details. StoryGraph's ISBN/UID and LibraryThing's ISBNs are read the same way.
- **After a failed import batch, the page says what a re-run would do — and Import can be pressed again.** It told everyone that re-running merges the rows already imported, which is true only of a Goodreads, StoryGraph or LibraryThing file: a libib or Nalanda re-run adds them again. It now says which, how many rows landed, and that nothing was imported when the first batch failed; the Import button no longer stays greyed out.
- **Deleting a shelf is an admin's, and its items go to the trash.** Any member could delete a whole shelf, and everything on it went for good — the one delete that skipped the trash. Now only an admin sees and can use **Delete shelf**, and the shelf's items wait in the trash for 30 days like any deleted item, restorable onto a shelf made again under the same name. The shelf itself is not restored.
- **A copy out on loan is still yours.** The Holding toggle could mark a lent book Not owned, bulk edit could do the same, the edit form could save fewer copies than were out — and a Not owned book with a loan out then took a **Borrowed from** record on top. Each is now refused where it writes, with the reason: the toggle and bulk edit's "Mark not owned" leave a lent copy alone (bulk counts it as skipped), the edit form won't save copies below what is out on loan — and saves nothing else of the form when it refuses — and a borrow is never recorded while a loan is open. The toggle also zeroes only a count of exactly 1, and the form's "borrowed, so not yours" check is made by the statement that writes, so neither can be raced by a save made meanwhile.
- **A trash restore happens once, whole.** A Restore clicked twice brought the item back twice, with its reads, reviews and loans doubled; a failure linking the tags left it restored without them and gone from the trash; and "Restored. Open it" could link to an item someone else added at that moment. The restore is now one batch that cannot land twice — the second finds nothing — its tags inside it (a failure leaves the item in the trash to try again), and the link is to the item the restore made. The CSV import links tags inside its batch the same way.
- **A restored book is itself to connections, or new — never another book.** Restored under another book's old number (two books added in the same second, the other trashed first), the book took that book's reference as connections hold it; now it keeps its own reference only when it comes back under its own number, and is otherwise a new book to them. A restore also leaves a series' total as it stands — one corrected since the book was deleted was being put back.
- **The trash's 30 days hold.** The purge ran only when something was deleted or the Trash page opened, so in a quiet month a deleted item's notes, location and borrowers stayed on past the 30 days and it could still be restored. Now every edit to any item lets go of what a trashed item held once its days are up — its line waits for the next delete or visit to go with its cover — and a restore past the 30 days is refused, with the reason.
- **Caps where there were none.** The item form took any number of tags of any length (bulk edit already stopped at 20 per action); a book took quotes past the 500 its Kindle import stops at, and a record or game took quotes though its page never shows them; a read took pages without end, and the item page listed every one. Now the form takes up to 50 tags of up to 100 characters each, a book holds at most 500 quotes and a record or game none, and one read holds at most 1,000 recorded pages — each refused where it writes, and each said on the page.
- **A household always keeps an admin.** Two admins removing each other at the same moment could leave no members at all, with first-run setup open to whoever came next. Removing a member is now refused outright — nothing of theirs cleared — unless another admin remains and the admin removing them is still here; the page says so.
- **A series merged by renaming names who did it.** Renaming a series to a name another series already has moves its volumes across, and each volume's History showed that change as nobody's ("—"). It now names the member who renamed it, as every other item change does.

### Upgrading
- **One migration, 0053: a new column on `login_attempts` (`username`), no data changed.** [Back up](../runbooks/backup-and-restore.md) first as before any migration, then deploy as usual. The table is throttling state, left out of backups and stale within minutes; nothing in it survives the hour.
- **A Discogs image typed with a trailing dot.** A cover URL typed as `https://i.discogs.com./…` — the fully qualified spelling of the same host — was fetched and stored. Every host check now reads a name as DNS does, case and trailing dot aside, so it is refused like any other Discogs image (ARCH.md §16 #67).
- **A cover over 5 MB is refused before it is read.** A cover URL pointing at a large file was downloaded whole and only then measured against the 5 MB cap, taking as much of the Worker's memory as the file had. The length the host declares is checked first, and the body is read a piece at a time and dropped the moment it passes the cap — in the app and in the laptop scripts alike.
- **A book scanned by its ISBN-10 is known again by its EAN-13.** An older printing's ten-digit ISBN was recorded in the ISBN-13 field as it was, so the shelf's ISBN-13 column, the export and "In your catalog" held ten digits, and a later scan of the same book's barcode wasn't recognised. The ISBN-10 is now kept as the ISBN-10, and the ISBN-13 it stands for is recorded beside it — Google Books' when it names one, else worked out from the ten — so either number finds the book.
- **An ISBN-10 ending in X is a book.** Typed into the Add page, `080442957X` lost its X, and the nine digits left were asked of Discogs as a record's barcode. It goes to the book providers as written, hyphens and spaces aside.
- **A board game whose description is all digits no longer fails the search.** BoardGameGeek's answer for a game such as *1830* — described as "1830" — was read as a number, and the whole page of results came back as "BoardGameGeek did not answer". Every description is read as text now, and a single game whose record can't be read is left out of the page rather than taking the page with it.
- **The search index is rewritten only when something it holds changes.** Every update of an item — a reading refreshed to what it already was, a shelf moved in bulk, a page recorded — deleted and re-inserted its search-index row, writing several rows for nothing against the free tier's daily allowance. The index's update trigger now fires only for the six columns it indexes: title, creators, description, notes, location and original title. Searching is unchanged.

### Upgrading
- **One migration, 0054: the search index's update trigger recreated with a column list, no data changed.** [Back up](../runbooks/backup-and-restore.md) first as before any migration, then deploy as usual. Nothing is rebuilt; the index's contents are as they were.
- **A Not owned item never claims a read on a share page.** A reading-log entry — a Goodreads import, a library book — showed "Read N times" and, with progress on for shares, a current page, as any owned book does. The rule is now as CLAUDE.md states it: while an item isn't owned, its share page and feed say "Not owned" and nothing about its reads. Owned, the same reading shows as before; connections are unchanged.
- **"Publish current view" names every filter a link leaves out.** The note under the button said so for Read by and Format only; with Borrowed from someone, Unread for years, Not played lately or the search box in the bar it read "(none — the whole shelf)" and the link showed more than the screen. It now lists each of them. None of these becomes publishable: a share link still carries only type, status, holding and sort.
- **Names from connections are cleaned, every one.** A comment's author, a borrow requester and a household's name from its descriptor or connect request kept control and direction-override characters that a feed entry's name had always had stripped; a crafted requester could reorder the text around it on Loans, in a notification and in the loan's borrower. All three are now cleaned as display names are, and a name that is nothing but such characters is refused.
- **Borrow requests count against the daily limit.** Comments and recommendations stop at a hundred messages to one household a day; asking to borrow didn't, so every request was queued and pushed. The hundred-and-first is now refused on the Borrowed page, neither sent nor queued, before the household is asked anything.
- **A message isn't dropped on a 404 or 401 that isn't the household's own.** Any 4xx but 429 was taken as a final refusal, so a household whose key was unset for a while — every connections route answers a plain not-found page then — or one behind a proxy answering 401 lost a queued acceptance, return notice or comment for good, and a request of ours was declined with "isn't available any more". Only an answer in the inbox's own words is final now; anything else leaves the message in the outbox, retried on page loads and delivered by their pull, for two days.
- **A member's feed entry carries no finish date.** With names on for connections, a per-person "finished" entry carried the book's `completedOn` — that member's own end date, beside their name — against the rule that the dates of anyone's reads never leave the instance. A member's entry now carries none; the household's own "finished" entry still says when the book was last finished, as before. Connected households never showed the field.
- **A disconnected household loses read access at once.** Each isolate kept a connection's key for a minute, and trusted the cached row for the connection's state too, so a household disconnected on one isolate could still read shared views, feeds and shelves from the others for up to a minute. The cache now serves the key alone; whether the connection still stands is read on every request.
- **A restored copy of the database can be kept away from the real households.** A production backup's connections name the real peers, and a copy's first page load pulled their outboxes and retried pushes against them. A new `FEDERATION_OFFLINE` variable stops every pull, push, notice and live read from such a copy, while what peers send it is still answered; the Connections page says so. Production never sets it — see Upgrading.

### Upgrading
- **A new optional runtime variable, `FEDERATION_OFFLINE`, for copies of the database only.** A plain variable — a `vars` entry in `wrangler.jsonc` or a line in `.dev.vars`, never a secret — set to anything (`1`) before the first page load of a backup restored anywhere but production, so the copy contacts none of the households its connections table names. **Production must leave it unset.** The [backup and restore runbook](../runbooks/backup-and-restore.md#a-production-backup-restored-locally--keep-it-away-from-the-real-households) has the steps (ARCH.md §16 #92). Nothing to do for a deployment.
- **One migration, 0051: a new `api_tokens` table, no data changed.** [Back up](../runbooks/backup-and-restore.md) first as before any migration, then deploy as usual. The backup's table order gains `api_tokens`.
- **One migration, 0052: a new column on `items` (`created_at`, empty until an import re-dates a book), no data changed.** [Back up](../runbooks/backup-and-restore.md) first as before any migration, then deploy as usual. Then, to date a catalogue imported from Goodreads before this version, re-import the same export with the box ticked ([runbook](../runbooks/import-from-goodreads.md#dates-added)).
- **Two migrations, 0049 and 0050: two new tables (`item_history`, and the `acting` marker, empty between writes) and one trigger on `items`, no data changed.** [Back up](../runbooks/backup-and-restore.md) first as before any migration, then deploy as usual. History starts at the upgrade; nothing is backfilled, and every item write sweeps what is older than 90 days. The backup's table order gains both tables.
- **One migration, 0048: a new `borrows` table, no data changed.** [Back up](../runbooks/backup-and-restore.md) first as before any migration, then deploy as usual. The backup's table order gains `borrows`.
